How to Check a MYOB AccountRight Import File Before Importing

A practical pre-import checklist for Sales – Items CSV and TXT files: formatting, numeric values, transaction separators, field lengths and comparison with your own AccountRight export template.

Import problems are easier to investigate before the file reaches MYOB AccountRight. A useful pre-import check focuses on the file itself: whether the structure is consistent, whether selected numeric fields contain clean values, whether transaction separators make sense, and whether the layout resembles the format you expect.

Scope: this guide focuses on MYOB AccountRight Sales – Items import files. A file can pass these checks and still be rejected for another reason. File checking also cannot verify records inside your company file, such as whether a customer, item, job or tax/GST code exists.

1. Keep the original import file unchanged

Before fixing anything, preserve the CSV or TXT file you received or generated. If you make a correction, create a separate copy. This gives you a clean source to compare against if an import behaves differently after a change.

2. Check the file structure

Start with the basics. Confirm that the delimiter and quoting are consistent and that rows follow the intended Sales – Items layout. Small structural differences can make a file difficult to interpret even when the visible values look reasonable in a spreadsheet.

  • Look for unexpected delimiters or quotation marks.
  • Check for missing or redundant blank transaction separators.
  • Confirm that records use a consistent column structure.
  • Be careful when saving through another application, which may alter CSV formatting.

3. Inspect numeric and amount fields

Numeric fields should contain values in the format expected by the import layout. Currency symbols, malformed numbers or other presentation formatting can turn a value that looks fine to a person into problematic import data.

Simple example

A value displayed as $5.00 may need to be represented as the plain numeric value 5.00 in a particular import field. A safe mechanical correction should change only the formatting that is known to be safe—not invent or recalculate accounting values.

4. Check field lengths

Some Sales – Items fields have practical length constraints. Long references or text values can therefore be worth checking before import. If a value exceeds a supported limit, review it rather than silently truncating business data.

5. Treat missing values carefully

Not every blank field means the same thing. For example, tax/GST information may depend on configuration elsewhere in AccountRight. Avoid filling missing business or accounting values merely to make the file look complete.

Likewise, a missing item identifier on a quantity-bearing Sales – Items row deserves attention, but a checker should explain the structural concern rather than pretend it has access to your company file.

6. Check arithmetic warnings in context

If the file contains quantity, price, discount and total information, make sure any arithmetic check accounts for the discount before reporting a mismatch. For example, quantity 2 × price 10 with a 10% discount produces a total of 18, not 20.

If the discount itself is malformed or ambiguous, it is safer to flag the underlying problem than to make a confident secondary arithmetic conclusion.

7. Compare with an AccountRight export template when possible

One practical way to reduce layout guesswork is to export the same type of data from AccountRight or an appropriate sample/company file and use that export as a reference template. Compare headers and structure with the file you plan to import.

A template comparison is useful evidence, but it still does not guarantee that every value in the new file is valid for your actual company file.

8. Create a corrected copy only for safe mechanical fixes

Automating a correction is appropriate when the change is mechanical and unambiguous. Examples can include supported formatting cleanup or separator repair. It is not appropriate to invent an item number, tax code, customer, account or other business value.

Pre-import checklist

  • Original CSV/TXT preserved
  • Correct Sales – Items import type confirmed
  • Delimiter and quoting checked
  • Transaction separators reviewed
  • Selected numeric fields contain clean numeric values
  • Currency-style formatting reviewed
  • Selected field lengths checked
  • Missing business/accounting values are not guessed
  • Discount-aware arithmetic checked where applicable
  • File compared with your own AccountRight export template when available
  • Any safe fixes written to a separate copy

What a file checker cannot tell you

A local import-file checker cannot know everything AccountRight knows. Without connecting to your company file, it cannot confirm that customers, items, jobs, accounts, tax/GST codes or other records exist or are configured correctly. It also cannot guarantee that AccountRight will accept a file.

The useful goal is narrower: catch common structural and formatting problems before you attempt the import, while preserving the original file and avoiding unsafe accounting guesses.
